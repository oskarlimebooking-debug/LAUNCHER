# Replace LayoutInflater wrap with viewInflaterClass for API 23 TextView crash + build release APK

## Problem

Field crash on the alps/A6_series API 23 head unit (release build 0.1.0):

```
Caused by: java.lang.ArrayIndexOutOfBoundsException: length=45; index=1264
    at android.content.res.StringBlock.get(StringBlock.java:65)
    at android.content.res.TypedArray.getString(TypedArray.java:195)
    at com.google.android.material.theme.MaterialComponentsViewInflater.e(SourceFile:11)
    ...
    at androidx.fragment.app.z.B   (fragment view inflation)
```

`MaterialComponentsViewInflater` crashes inflating a `TextView` on the way up from `HomeFragment` → child fragments (first offender: `fragment_weather.xml`'s `condition` TextView). This is a known API 23 / Material Components / aapt2 StringBlock interaction.

The current attempted mitigation (`SafeInflaterFactory` + `MainActivity.getLayoutInflater()` override + `wrapLayoutInflaterFactory()`) **never actually installs** on API 23 because `LayoutInflater.setFactory2()` permanently locks the inflater (`mFactorySet = true`) after the FIRST call, and `AppCompatActivity.super.onCreate()` already installs `AppCompatDelegate` as factory2 before our code runs. The log shows every `setFactory2` attempt swallowing `IllegalStateException: A factory has already been set on this LayoutInflater` — so the unwrapped Material inflater runs and crashes.

## Fix

Replace the broken factory-wrap approach with the AppCompat-supported `viewInflaterClass` theme attribute. AppCompatDelegate instantiates the class once per activity, **before** factory2 is locked, so substitution is guaranteed.

1. **New class** `app/src/main/java/com/oskar/retrolauncher/SafeMaterialComponentsViewInflater.kt`:
   - Extends `com.google.android.material.theme.MaterialComponentsViewInflater`.
   - Overrides each `createXxxView(Context, AttributeSet)` method that the Material inflater provides (at minimum `createTextView`; also `createButton`, `createCheckBox`, `createRadioButton`, `createAutoCompleteTextView`, `createMultiAutoCompleteTextView`, `createCheckedTextView`, `createImageView`, `createEditText`, `createSpinner`, `createSeekBar`, `createImageButton`, `createRatingBar`, `createToggleButton`).
   - Each override calls `super.createXxxView(...)` inside `try { ... } catch (e: ArrayIndexOutOfBoundsException) { ... }` and on AIOOBE falls back to the AppCompat widget directly (e.g. `androidx.appcompat.widget.AppCompatTextView(context, attrs)`).
   - Log the swallow via `Timber.w(e, "SafeMaterialComponentsViewInflater fallback for <view>")` so it's visible in future logs.

2. **Theme update** `app/src/main/res/values/themes.xml`:
   - Add `<item name="viewInflaterClass">com.oskar.retrolauncher.SafeMaterialComponentsViewInflater</item>` to `Theme.RetroLauncher` (the base style — variants inherit).

3. **Remove dead code** that cannot work on API 23:
   - `MainActivity.getLayoutInflater()` override (lines 167-181).
   - `MainActivity.wrapLayoutInflaterFactory()` (lines 183-195) and the call site (lines 54-56).
   - `app/src/main/java/com/oskar/retrolauncher/SafeInflaterFactory.kt`.
   - `app/src/test/java/com/oskar/retrolauncher/SafeInflaterFactoryTest.kt`.
   - The `LayoutInflaterCompat` and `LayoutInflater` imports in `MainActivity` if no longer used.

4. **Build the fixed APK** for the head unit:
   - `cd retro-launcher && ./gradlew :app:assembleStandardRelease`
   - Output: `retro-launcher/app/build/outputs/apk/standard/release/app-standard-release.apk`.
   - Bump `versionCode` from `1` → `2` and `versionName` from `"0.1.0"` → `"0.1.1"` in `app/build.gradle.kts:20-21` so the head unit accepts the upgrade install.

## Notes

- Keep the catch narrow (`ArrayIndexOutOfBoundsException` only). Broader catches mask unrelated bugs.
- The AppCompat fallback drops Material text styling on API 23 specifically — acceptable trade-off since the alternative is a crash, and Material 3 theming is mostly cosmetic for a launcher.
- `Theme.RetroLauncher.Preferences` extends `PreferenceThemeOverlay` (not `Theme.RetroLauncher`), so it's unaffected — preferences screens use AppCompat's stock inflater.
- After T2.4/T2.5 (already done) reported "no crashes," this slipped through because the smoke test ran on an emulator without the exact OEM aapt/StringBlock interaction. Don't try to reproduce in CI; the human-gated AC is the source of truth.
- Do not skip git hooks when committing. If `arch check` fails, fix the file rather than bypassing.
