# Systematic API 23 compatibility audit of all source files

Audit every source file that ships in the standard flavor for API 23 compatibility. The initial exploration found the codebase is well-designed for API 23, but verify edge cases that could cause installation-time or first-launch crashes.

## Scope

- All `src/main/java/**/*.kt` and `src/main/java/**/*.java`
- Manifest entries and resource qualifiers
- Library transitive dependencies that might pull in API 24+ classes

## What to check

1. Every `@RequiresApi` annotation — verify there's a runtime `Build.VERSION.SDK_INT` guard at EVERY call site, not just the method signature
2. Every `import` of API 24+ classes (even those guarded at the call site) — verify the class symbol isn't referenced in a way that triggers eager class loading
3. Library AAR dependencies — check for `uses-sdk` / `minSdkVersion` conflicts
4. Kotlin stdlib compatibility with API 23 (coroutines, reflection, inline classes)
5. `META-INF` service loader files in the merged APK — some libraries (WorkManager, Room) register services that might fail on API 23
